## 1. 教师账号管控传导

### 动作：teachers · 新增教师
- 管理端入口：`src/app/(main)/teachers/_components/TeacherForm.tsx:127-128`（submit → `POST /api/teachers`，mode=add 时 method=POST）。
- 写入点：`src/app/api/teachers/route.ts:189-208` 构造 Teacher 字段；`:228-260` `$transaction` 内先建/恢复 Teacher，再 `user.create/update`（`role:'teacher'`、`status:'active'`、`division`、`teacherId` 关联），并写两条 ActivityLog。
- 教师端消费：`src/lib/auth/guards.ts:98-112` requireTeacherUser 每请求 `resolveTeacherForUser` 实时解析档案；`src/app/api/teacher/dashboard/route.ts:14` 实时返回 `teacher.{id,name,gender,avatar,subjects,tierLevel}`。
- 家长端消费：无。
- 结论：**真连通**。
- 证据：
  - `api/teachers/route.ts:250-259`：`user.create({ data: { email, password: hash, name, role:'teacher', status:'active', division, teacherId } })`。
  - `guards.ts:103-110`：`const teacher = await resolveTeacherForUser(prisma, {…}); if (!teacher) throw new AuthError('未绑定可用的教师档案')`。
  - `api/teacher/dashboard/route.ts:14`：`teacher: { id: teacher.id, name: teacher.name, … tierLevel: teacher.tierLevel }`。
- 实测（SQL，`o1-sql-1.txt` Q1b/Q1c）：Teacher 表 ACTIVE 29、RESIGNED 4；User 表 role=teacher 中 active 8、disabled 21；另有 Q1d 14 个 role=teacher 但 `teacherId` 为空的孤立账号（无法解析教师档案，登录后被拦截）。29 个在职 Teacher 与 8 个 active 教师账号并不一一对应——多数在职 Teacher 尚未建登录账号，属数据现状而非传导断裂。
- 修复方向：新增教师事务已一致；建议补「在职 Teacher 缺 User 账号」的后台提示。风险级别：零风险改代码。
- 确定性：[已核实]
