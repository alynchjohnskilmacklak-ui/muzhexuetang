## 1. 逐条固定结构

### 1.1 家校沟通 `messages`

- **入口页面**：`src/app/parent/messages/page.tsx`（服务端鉴权）→ `messages/client.tsx`。
- **动作清单与写入点**：
  1. 新建留言：`POST /api/messages`（`messages/client.tsx:348`）。校验：`findParentChild(await getParentChildren(prisma, user.id), studentId)`，非本人孩子 403（`api/messages/route.ts:126-127`）。写入 `ParentMessage`：`parentId=user.id, studentId=child.id, teacherId（按最近课次/报名候选解析）, subject, title`，首条回复 `ParentMessageReply` role=parent、`isReadByParent=true, isReadByTeacher=false`（`route.ts:195-211`）。
  2. 回复：`POST /api/messages/:id/reply`（`client.tsx:372`）。归属校验：`message.parentId !== user.id` → 403（`api/messages/[id]/reply/route.ts`）。写入 reply；家长回复 `isReadByParent=true/isReadByTeacher=false`，教师回复反向（`:56-57`）。
  3. 标记已读：打开会话 `GET /api/messages/:id`（`client.tsx:268`）在服务端按当前角色回写已读（`api/messages/[id]/route.ts:56-62,71-72`）。
  4. 另有 `POST /api/messages` 用于关闭/刷新类动作（`client.tsx:400`）。
- **教师端可见性**：`src/app/teacher/messages/page.tsx` 读 `/api/messages`；访问域 `getAccessibleParentMessageWhere`（`lib/parent-message-access.ts:53-71`）：parent=`parentId=actor.id`，teacher=反馈任课教师或 `teacherId=actor.teacherId`，admin=学部。教师未读数 `api/messages/unread-count/route.ts:31-32`（家长回复 `isReadByParent=false` 口径）。
- **管理端可见性**：`src/app/(main)/parent-messages/client.tsx` 读 `/api/messages`，同表同字段；另在沟通中心以 Tab 内嵌同组件（`(main)/communication-center/page.tsx:9,26` "家长留言" Tab）。
- **已读双向回写**：字段在 `ParentMessageReply`（schema.prisma:2236-2237）；`ParentMessage` 主表本身无已读字段。家长视角回写 `isReadByParent`、教师视角回写 `isReadByTeacher`，双向闭环存在。
- **SQL 实测（§5 Q6/Q6b/Q6c）**：`ParentMessage` 39 条（OPEN 15 / CLOSED 12 / REPLIED 8 / READ 4，全部挂 teacherId）；Reply 69 条（parent 48、teacher 12、admin 11）；**家长发出但教师未读 8 条**；教师发出但家长未读 2 条。
- **风险/断点**：① 教师账号未绑定 User 时，`notifyTeacherAboutParentMessage` 静默丢弃（仅 console.error，沿用 T5）；② 教师端不消费 `Notification` 表，留言提醒类通知在教师侧是孤岛（§1.2）。

### 1.2 通知 `notifications` / `notifications/[id]`

- **列表读点**：`parent/notifications/page.tsx:21-31`，where = `{ userId, ...visibleNotificationWhere, ...parentVisibleNotificationWhere(userId) }`；归档分支 `:23-24` 同加 scope。
- **归属过滤复核（前轮 O1 判"不复核 studentId"）**：`parentVisibleNotificationWhere`（`lib/business-visibility.ts:97-103`）= `OR([{ studentId: null }, { student: parentLinkedStudentWhere(parentId) }])`；`parentLinkedStudentWhere`（`:84-90`）= `OR([{parentId},{parentUserId}])` + `status<>'INACTIVE'` + `deletedAt:null`。**本轮确认代码已叠加该 scope**（与 O1 记录的旧口径不同，见 §10）。
- **已读写入**：
  - 单条 / 分类 / 归档已读：`POST /api/parent/notifications/mark-read`（`client.tsx:357,375,399`）；服务端按 `userId + parentVisibleNotificationWhere` 圈定 updateMany（`mark-read/route.ts`）；留言类同步 `message: { id in messageIds, parentId: userId }`（`:132`）。
  - 全部已读：`POST /api/parent/unread-counts/read-all`（`client.tsx:376`）；`api/parent/unread-counts/read-all/route.ts:24,62` 同口径。
  - 详情页服务端读回写：`notifications/[id]/page.tsx:120-133`，未读时 `updateMany({ where: { id, userId, ...scope, read:false }, data:{ read:true, readAt } })`；并按来源回写反馈回执 / 动态 `isReadByParent` / 试卷 `isReadByParent+readAt`（`:137-156`）。
- **解绑后旧孩子通知**：scope 已排除 INACTIVE / 软删 / 换绑到他人的学生；通用通知（`studentId=null`）仍按 `userId` 可见。SQL 复核：家长角色接收通知 `bound_other=0`（§5 Q3/Q4）。
- **详情越权**：`[id]/page.tsx:23-30` 必须同时命中 `id + userId + scope`，否则 `:47` redirect 回列表；关联反馈/动态/试卷再按 `parentStudentIds` 二次过滤（`:71,89,104`）。**拿别人通知 id 不可见**。
- **未读数**：`GET /api/parent/notifications/unread-count`（`:15-17`）与 `GET /api/parent/unread-counts` 均带 `parentVisibleNotificationWhere`。
- **断点**：教师账号收到的 `Notification`（留言/提醒/请假）教师端无读点、无已读回写（沿用 T5 结论，本轮未重验教师 UI）。

## 8. Top 断点 / 修复建议 / 风险

### 断点（按优先级）

1. **【中】缴费账单家长端是只读壳，无业务发起通道**：`fees` 页无开票 / 凭证上传 / 退费入口；`Fee` 表 0 行，管理端虽可经 `/api/fees` 建单，但家长侧看不到任何可操作项。修复方向：若产品需要家长发起，补"上传缴费凭证 / 申请退费 / 开票申请"三个写端点与对应表单；若定位为管理端单方记账，则在页面明示"账单由校区工作人员登记"。
2. **【中】志愿咨询缺教师端 UI**：家长 POST `/api/volunteer/consultation` 只通到管理端 `/main/volunteer`；reply 路由放行 teacher 但 `teacher/**` 无页面，任课教师无法在教师侧看到/回复咨询。修复方向：教师端咨询列表页，或明确该职能仅由管理员承接。
3. **【中】会员权益半硬编码**：`SystemConfig.membershipBenefits` 当前 NULL；客户端 `LEVEL_SUMMARY/COMPARISONS/LEVEL_META` 不可配置。管理端改等级规则/对照文案不会反映到家长端。修复方向：把标签、对照行、规则文案也纳入配置解析，或确认产品接受硬编码后移除配置回退分支。
4. **【中】AI 无持久化与配额扣减**：对话不落库、配额内存 Map 重启清零、全角色共用端点无用量审计。修复方向：若需追溯/限额，补 conversation/message 表与配额扣减；至少把限流桶落到 Redis 或 DB。
5. **【低-中】静默吞错**：`ParentStudyHallWorkspace.tsx:58` 已读回写失败无提示；`AssistantBriefing.tsx:230-237` 简报加载失败静默降级。修复方向：补错误状态与重试入口，避免角标/卡片长期假正常。

### 风险

- **数据风险**：教师账号 31 条 PARENT_MESSAGE + 13 条 REMINDER + 2 条 leave 通知未读停滞（T5 孤岛结论延续）；家长侧 8 条家长回复教师未读。
- **口径风险**：成长档案历史口径（`parentStudentHistoryWhere`）不排除 INACTIVE 学生，与 linked 口径不同；资料库 `/api/parent/materials` 不按学员隔离。
- **前端风险**：`volunteer/client.tsx:91` 提交问题无 `.catch`，网络异常会产生未捕获 rejection。

### 不建议本轮改动

- 30 个 `api/parent` 路由归属校验闭环完整，无越权修复项。
- 通知列表/详情/已读回写的归属 scope 已补齐，无需重复改造。
