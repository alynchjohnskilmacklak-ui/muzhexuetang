## 二、逐项证据

### B1-a 圆角：12 套 px 值，规范区间只占 13%

`globals.css` 共 **342 处** `border-radius`（**340** 条声明 + 2 处出现在 `@supports` 条件与注释）。取值分布（按次数降序，前 25）：

**结论**：16–20px 合计 **45 条（13.2%）**；小于 16px 合计 **185 条（54.4%）**；pill/圆形 **78 条**；`inherit`/`0`/其余 24px 等 **32 条**。
**根因**：令牌体系本身把容器圆角定在 12px —— `--radius-lg: 12px`、`--radius-container: var(--radius-lg)`、`--radius-interactive: var(--radius-md)`（8px）。也就是说"用令牌"和"符合 16–20px 卡片规范"在系统里是矛盾的。

### B1-b 阴影：82% 是裸写

`--shadow-*` 三档定义齐全（`--shadow-raised: 0 1px 2px rgba(26,18,1,.04), 0 8px 24px rgba(26,18,1,.04)`；`--shadow-overlay: 0 18px 48px rgba(26,18,1,.12), 0 2px 8px rgba(26,18,1,.06)`；`--shadow-card: 0 8px 24px rgba(26,18,1,.04)`），但 **130 条 `box-shadow` 声明里只有 23 条（17.7%）用令牌**，107 条裸写（其中 21 条是 `none`/`none !important` 的复位，实际"造型阴影"裸写 **86 条**）。

出现最多的裸写值（同一语义的阴影被写成多个近似值）：

| 次数 | 值 |
|------|----|
| 4 | `0 4px 12px rgba(20, 60, 50, .05)` |
| 2 | `0 6px 14px rgba(46, 110, 83, .26)` |
| 2 | `0 0 8px rgba(201,164,92,.45)` |
| 2 | `0 5px 16px rgba(26, 18, 1, .07)` |
| 2 | `0 6px 16px rgba(20, 60, 50, .12)` |

这 5 组共 12 条，剩下的 74 条几乎每条都是"独一无二"的阴影值 —— 说明阴影从来没有收敛，而是逐页手调。

### B5 会员等级主题：约定了的值都在，但压在一层 `!important` 上

**色值逐项比对（`src/constants/membership.ts`）**

| 项 | 规范 | 实际 | 判定 |
|---|------|------|------|
| SVIP bg | `#F8F3E7` | `:47` `bg: '#F8F3E7'` | ✓ |
| SVIP border | `#C9A45C` | `:48` `border: '#C9A45C'` | ✓ |
| SVIP accent | `#123C35` | `:49` `accent: '#123C35'` | ✓ |
| SVIP text | `#123C35` | `:50` `text: '#123C35'` | ✓ |
| SVIP gold | `#C9A45C` | `:51` `gold: '#C9A45C'` | ✓ |
| NORMAL/VIP accent | — | `:33` `#3E8E6E` / `:41` `#F0875B` | 未被改动 |

**权益区墨绿渐变（`globals.css`）**

```css
/* globals.css:3067-3069 */
.parent-membership-benefits--svip {
  background: linear-gradient(150deg, #123C35 0%, #0B2A25 100%) !important;
  border: 1px solid rgba(201,164,92,.5) !important;
}
```

渐变端点与金边**与红线完全一致**。但请注意这里的层叠结构：

- `:2948` 先定义了 `.parent-membership-benefits--svip { background: #F8F3E7; border-color: #C9A45C; }` —— **浅色**（奶油底）。
- `:3067` 再用 `!important` 覆盖成墨绿渐变。
- 也就是说：**SVIP 权益区的墨绿是靠 `!important` 压出来的，底下始终躺着一层浅色规则**。任何人删掉 `:3067`、或再加一条特异度更高（如 `#mobile-root.parent-page--svip ...`）的浅色规则，就会立刻回退成奶油色 —— 这正是红线 3 要防的现象。**建议（不实施）**：把 `:2948` 改成墨绿、让 `!important` 变成可选，去掉"覆盖"关系。

**`:not(.parent-membership-benefits)` 是否仍生效**：两处仍在

```css
/* globals.css:227-228 */
.brand-background-route .parent-dashboard-home .parent-dashboard-section:not(.parent-membership-benefits),
#mobile-root[data-brand-background='true'] .parent-dashboard-home .parent-dashboard-section:not(.parent-membership-benefits)
/* globals.css:3057 */
.parent-dashboard-home--svip .parent-dashboard-section:not(.parent-membership-benefits)
```

两处都还在，且没有在文件后面被同名选择器重新定义（Grep `parent-dashboard-section` 未发现更晚的覆盖规则）。**生效**。

**重复声明（19 行）**：`:3073-3085` 把同一批 SVIP 子元素规则写了两遍（一遍带 `!important`、一遍不带），例如 `__head h2` 在 `:3073` 与 `:3079` 各一次、`.parent-membership-benefit` 在 `:3074` 与 `:3081` 各一次。不影响渲染结果（同值），但会让人误以为有两套主题，属可维护性偏差。
