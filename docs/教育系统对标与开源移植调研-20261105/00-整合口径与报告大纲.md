# 00・整合口径与报告大纲（内部写作规范，不对外交付）

> 本文件是报告总装的判断口径。写作子任务必须严格遵循本文件的优先级判定与分类口径；若与 01/02/03/04 的证据冲突，以证据为准，并在报告中标注 "与口径不一致"。

## 一、报告定位

读者：牧哲学堂的开发者 / 负责人（单人主导的全栈项目，机构规模为单校区、几十到一两百名学员的 K12 教培）。

报告目的：回答三个问题 ——① 优秀教育系统有而我们没有的是什么；② 哪些开源项目能直接搬进来；③ 按投入产出该怎么排期。

语气：务实、敢下判断、不制造焦虑。**允许并鼓励出现 "这个不用补" 的结论**，且必须给出理由。

## 二、三类结论的分类口径（写作时必须逐条标注）



* `功能缺口`：业务对象或流程整体不存在（如无作业提交模型、无线索模型）。

* `质量缺口`：骨架已在，差最后一公里（有表无界面、有接口无消费方、有配置无执行、有统计无分析）。

* `规模不匹配`：能力存在但对当前机构规模是过度设计（不算缺口，进 "不补" 清单）。

> 关键判断：本次核查显示牧哲学堂的问题
>
> **绝大多数是 "质量缺口" 而不是 "功能缺口"**
>
> ——89 个 model、296 个 API 已经覆盖了教培经营的绝大部分对象，真正的短板是 "数据进去了但没被用起来"。报告必须把这句话放在最前面，否则会误导排期。
