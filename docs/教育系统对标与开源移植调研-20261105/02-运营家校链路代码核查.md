## 核查中的新发现（14 条之外的运营侧薄弱点）

1. **NotifyConfig 与 RoleConfig 同为"只读单例 + PATCH 409"，业务链路完全不消费**：除 `settings/notify`、`settings/roles` 两个路由外，全代码无任何业务读取其字段；通知开关、低课时阈值、教师看费用/看他人学员的门控实际由服务端硬编码控制，配置页仅是展示壳。证据：`prisma/schema.prisma:1425-1442`；`src/app/api/settings/notify/route.ts:14-28`；`src/app/api/settings/roles/route.ts:14-28`；grep `notifyConfig|roleConfig` 仅命中上述路由。
2. **财务报表成本恒为 0，毛利指标不可信**：`reports/summary` 每月 `expense` 初始化为 0，`profit = income − expense`，即利润恒等于收费收入；`TeacherSalaryTransaction` 工资台账独立存在，但未作为成本进入财务报表。证据：`src/app/api/reports/summary/route.ts:134-147`；`prisma/schema.prisma:1869-1898`；`src/app/api/settings/export/finance/route.ts:20-32`（仅 Fee 导出）。
3. **退款/部分缴费状态在代码中不可达**：`REFUNDED`/`PARTIAL` 只出现在前端状态标签映射，`fee.create` 唯一入口落 `paid`，`fees/[id]` PATCH 只能清空 paidAt，无退款或部分缴费写接口。证据：`src/app/api/fees/route.ts:224-239`；`src/app/api/fees/[id]/route.ts`；`src/app/(main)/students/[id]/page.tsx:817`。
4. **企微家长群发是"草稿 + 人工确认"链路，不是自动直发**：`add_msg_template` 生成群发任务后置 `pending_confirm`，需成员在企业微信客户端确认，cron 轮询 `get_groupmsg_send_result` 回填 sent/failed/limit_today；未确认期间家长不会收到消息。证据：`src/lib/qywx.ts:304-340,342-360`；`src/app/api/cron/retry-notifications/route.ts:58-84,224-241`。
