## 1. 核实方法与取数时间说明

1. **GitHub 结构化事实**：优先调用 GitHub REST API `https://api.github.com/repos/{owner}/{repo}`，读取 `stargazers_count`、`pushed_at`、`archived`、`license.spdx_id`、`license.name`、`language`、`description`、`default_branch`。
2. **许可证原文复核**：API 返回 `NOASSERTION` / `null` / `Other` 时，拉取仓库 raw `LICENSE` / `LICENSE.md` / `LICENSE.txt` 原文核定；API 元数据与原文冲突时以 LICENSE 原文为准，并在条目内注明。Node/TS 包另用 npm registry（`registry.npmjs.org/{package}`）交叉核验 `license` 与 `time.modified`。
3. **Gitee 项目**：走 Gitee API v5（`/api/v5/repos/{owner}/{repo}`）取 star、`pushed_at`、`language`；许可证读仓库 README / 协议 wiki / `composer.json` 原文。
4. **未核实处理**：无法打开、仓库不存在或许可证无任何声明的，标注"未核实/未声明"，不凭记忆补 star、许可证或仓库地址；不引用已归档（archived）或已删除项目。
5. **口径限制**：
   - `language` 为 GitHub 按代码字节估算的主语言，多语言项目仅作参考；
   - 许可证影响部分只做**事实陈述**（宽松/copyleft/附加条款分别约束什么），不构成法律意见；商用前应由法务逐条复核 LICENSE 原文；
   - 本次候选池**未出现 SSPL、BSL 许可证项目**；若后续引入 MongoDB 等 SSPL 组件，需单独评估。
6. **检索缺口（如实记录）**：
   - **课堂实时互动**（随机点名 / 抢答 / 投票 / 答题器 / 课堂计时）：GitHub、Gitee 检索结果以课程作业级 Demo 为主，未发现成熟、活跃、协议宽松、可直接嵌入 React 三端的开源组件，故未纳入清单；该方向建议自研轻量组件。
   - **中文发音评测 / 朗读打分**：开源侧仅有 ASR 转写引擎（见不建议表 whisper / FunASR / PaddleSpeech / whisper.cpp），未检索到成熟的中文音素对齐 + 发音打分开源算法库；朗读评分需在 ASR 转写基础上自研对齐与评分层。
   - **独立题库组卷算法 / 错题本组件**：开源实现多内嵌在整套考试系统内，无可单独抽取、宽松许可的算法库；现有静态题库 + 在线判分已落地，本组未推荐外部替代。
   - **独立作品集组件**：未找到可移植的成熟开源作品集模块；现有 StageSummary / PerformancePost / FileAsset 已覆盖基础作品沉淀。

- **许可证**：MIT Expat 核心；`ee/` 目录为独立商业许可证（仓库 LICENSE 原文：`ee/` 目录内容按 `ee/LICENSE` 授权，其余内容为 MIT Expat；API 标 NOASSERTION）。

- **可移植能力**：前端埋点 SDK + 分析建模；可建教学漏斗（报名 → 到课 → 课消 → 续费）、教师/家长端行为路径与留存。
- **接入改造点**：
  - 认证：内部对接；

- **许可证事实影响**：核心 MIT；**不得使用 `ee/` 目录与 enterprise 镜像**（商业许可）。

- **工作量**：大（≥1 人月：部署 + 埋点 + 指标建模 + 合规处理）。
- **推荐度理由**：若只做通用 PV 统计不必上 PostHog；确需产品级漏斗/留存/回放分析时再旁挂。

- **工作量**：小–中（策略迁移与中间件接入 ≤3 人日起步；复杂 ABAC 1–2 人周）。
- **推荐度理由**：出现细粒度/属性化授权需求时引入；纯角色权限场景不必替换现有实现。

## 4. 整套系统替换评估（Moodle / Frappe LMS / EduSoho）

> 结论先行：**三个系统都不建议替换现有平台**。它们均以"课程内容承载 + 在线学习交付"为中心，而本平台核心价值在机构经营链路（排课—考勤—课消—薪资—反馈—家校推送）与三端私有业务逻辑；替换等于把已上线的私有逻辑再实现一遍，并额外承担栈迁移、协议与合规成本。

### 4.1 迁移代价的六个统一维度

1. **数据模型冲突**

## 5. 许可证风险提示（事实说明，非法律意见）

### 5.1 宽松许可（MIT / ISC / BSD-2-Clause / Apache-2.0）

- 典型：Tiptap、Excalidraw、Sharp、Yjs、Formily、Novu、Apprise、Casbin、OR-Tools、Uppy、tus-node-server、Superset、RAGFlow、AnythingLLM、Whisper、whisper.cpp、FunASR、PaddleSpeech、PaddleOCR、RapidOCR、Tesseract、LiveKit、hls.js、Keycloak、ntfy 等。
- 事实影响：内部自用、对外提供 SaaS、二次分发一般均允许；义务通常是**保留版权声明与许可文本**；Apache-2.0 另含专利授权与修改声明条款。
- 注意：宽松许可不代表可以移除版权声明；多许可混合仓库（如 Liveblocks、PostHog、Metabase）需按目录/包分别适用对应许可证。

### 5.2 GPL 系 copyleft（GPL-2.0-or-later / GPL-3.0）

- 典型：Moodle（GPL-3.0）、Chamilo（GPL-3.0）、Matomo（GPL-3.0）、MaxKB（GPL-3.0）、LimeSurvey（GPL-2.0-or-later）、DataEase（修改版 GPLv3）。
- 事实影响：**分发**（向第三方交付二进制/容器镜像等）时需提供对应源码并以同许可证开放；纯内部使用通常不触发分发义务；GPL 本身不因 SaaS 网络使用而强制开源（与 AGPL 区别）。
- 自建 Docker 场景：若将含 GPL 组件的镜像对外交付或分发，需评估源码提供方式；修改 GPL 代码后内部自用与对外提供服务的边界建议法务确认。

### 5.3 AGPL-3.0（网络 copyleft）

- 典型：Frappe LMS、Canvas LMS、Open edX、ClassroomIO、Grafana、Metabase 核心；Liveblocks 的自托管 server 包。
- 事实影响：在 GPL 基础上增加**网络使用条款**——用户通过网络与软件交互即视为获得源码获取权；修改后通过网络对外提供服务，需向该网络用户提供修改版源码。
- 本平台为对外提供服务的经营性系统，引入 AGPL 组件（尤其修改其源码或嵌入服务端）前，须由法务评估网络服务场景下的开源义务；优先选 MIT/Apache 替代方案。

### 5.4 自定义 / 源码可见但非标准 OSI 许可

- 典型：
  - **Dify**：修改版 Apache-2.0，附加多租户环境运营限制 + 前端 LOGO/版权保留；
  - **FastGPT**：修改版 Apache-2.0，附加同类多租户 SaaS 限制 + 控制台 LOGO 保留；
  - **DataEase V3**：修改版 GPLv3，附加 LOGO/版权不得移除；
  - **tldraw**：自定义许可，生产环境使用需商业/试用 License Key，含 Key 校验与使用数据上报；
  - **EduSoho**：自定义 EULA，非商业免费、商用需授权、须保留页脚链接、禁止派生分发；
  - **PostHog `ee/` 目录 / Metabase `enterprise/` 目录**：商业许可证，与核心开源许可分开。
- 事实影响：这些项目虽然源码可见，但**不适用宽松开源许可的默认假设**；多租户、商用、logo 移除、二次分发、生产上线等场景须逐条对照 LICENSE 原文；拿不准时按"需单独获取商业授权"处理。

### 5.5 SSPL / BSL（本次候选池未出现，提示项）

- 本次核实的 65 个仓库未出现 SSPL（MongoDB 服务器端公共许可）或 BSL（商务源码许可）项目。
- 后续若引入 MongoDB、特定商业源码数据库/消息中间件，需单独核对其许可：SSPL 对外提供服务可能触发整套服务源码开放义务；BSL 通常在转许可期内限制商用/托管。

### 5.6 混合许可仓库的落地核对清单

1. 逐个目录/子包确认适用许可证（仓库根 LICENSE 可能只覆盖部分代码）；
2. 区分"核心开源"与"enterprise/ee 商业目录"，镜像构建与代码引用均不得混入商业目录；
3. 前端 LOGO/版权保留条款在二次品牌化改造前核对；
4. 第三方依赖（npm/Python/系统库）单独扫描许可证，避免传递性 copyleft；
5. 本文事实陈述不替代法律意见，对外商用与 SaaS 上线前由法务复核 LICENSE 原文。
