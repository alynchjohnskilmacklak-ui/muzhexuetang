### 2.2 名单（lesson-roster）

```
管理端在单课排课 PATCH /api/schedules/[id] body.studentIds
  ├─ INTENSIVE 班 → upsert Enrollment(ACTIVE) + 全量重写 ClassLessonStudent 快照 ✓
  └─ 普通班 → 把该班所有 ACTIVE Enrollment 全置 WITHDRAWN，再 upsert 传入学生为 ACTIVE
       ⚠ 半通：这是"整班覆盖"而非"加减名单"，且 totalHours/remainHours 硬写 1（行 257），
         不调用 syncStudentHourSnapshot 之前先把所有原学生置 WITHDRAWN，再 upsert，
         会让被剔除学生的 remainHours 随 enrollment 一起丢（虽然后面 syncStudentHourSnapshot 会重算，
         但 WITHDRAWN 报名的 remainHours=1 被持久化）。

教师端点名名单 GET /api/class-lessons
  └─ resolveSubjectLessonStudentIds(snapshot优先；历史课次若有快照则冻结)  ✓ 与管理端写入口同口径

家长端课节详情 GET /api/parent/today / hours-leaderboard / materials/lesson-previews
  └─ 均通过 resolveSubjectLessonStudentIds 收名单；CANCELLED 已被上层过滤  ✓

backfill 脚本 scripts/backfill-empty-future-lesson-rosters.ts
  └─ dry-run 默认；--apply 才写；planFutureLessonRosterBackfill 仅补"未来/SCHEDULED/未考勤/未结算/
     无快照/有 ACTIVE 报名"的课次。
     SQL 实测：未来 SCHEDULED 课次 264 节，其中空名单 22 节（第六轮基线 592/160）。
     → backfill 已跑过（160→22），但仍有 22 节未补；脚本幂等，可择期再 dry-run 复核后 --apply。
```
