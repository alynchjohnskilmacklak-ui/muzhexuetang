### 1.4 字体层结论

- `public/` 与 `src/` 内**没有任何本地 webfont 文件**（无 `.woff/.woff2/.ttf/.otf/.eot`）；未使用 `next/font`，未外链 Google Fonts。
- 字体走 CSS 变量映射的系统字体栈：`--font-geist-sans` / `--font-serif-cn` / `--font-geist-mono`（`src/app/globals.css`），回退 `-apple-system / Segoe UI / Roboto / Microsoft YaHei / Noto Serif SC` 等。
- CSP `font-src 'self' data:` 与上述结论一致。
- **字体层可优化字节 = 0**；后续若引入 webfont，需单独做子集化与 `font-display: swap`。

**建议补法（`next.config.ts` 新增 headers，示意）**

```ts
// 稳定 logo / 图标：长缓存。前提见下方"immutable 落地前提"
{ source: '/brand/:path*',    headers: [{ key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }] },
{ source: '/icons/:path*',    headers: [{ key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }] },
{ source: '/UI_picture/:path*', headers: [{ key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }] },

// 内容可能更新的素材：7 天 + 协商缓存
{ source: '/stickers/:path*',  headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/avatars/:path*',  headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/services/:path*', headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/marketing/:path*',headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/volunteer/:path*',headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/picture/:path*',  headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/bg/:path*',       headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },
{ source: '/audio/:path*',    headers: [{ key: 'Cache-Control', value: 'public, max-age=604800, must-revalidate' }] },

// 头像低频变更，由 1 天提至 7 天
// 将 /people/:path* 的 max-age 由 86400 调整为 604800
```

**`immutable` 落地前提（不可省略）**

1. `immutable` 意味着浏览器在有效期内**不再发校验请求**；只有"文件名带内容哈希 / 改图必须改名（加 hash 或 `?v=` 版本后缀）"的资源才能用。
2. 现有 `/images/*` 已是 immutable，但 `images/` 内 logo、题面若以同名覆盖更新，会被旧缓存卡住——后续更新须走改名。
3. 贴纸、头像、服务海报等**会被同名替换**的素材，先用 `max-age=604800, must-revalidate`，不要上 `immutable`。
4. 静态 HTML（home/about.html）引用的 webp 若换图，需同步检查 HTML 内文件名是否带版本号。

### 4.4 `_next/image` 链路复核

配置：`formats: ['image/webp','image/avif']`；`deviceSizes:[375,750,828,1080,1200]`；`imageSizes:[64,128,180,256,384]`；`minimumCacheTTL: 86400`；`compress: true`。

- **源图 1254px > 优化器上限 1200px**：优化器只降采样、不放大；请求 ≤1200 档时从 1254 源重编码一次，变体缓存 1 天。源图本身由静态处理器按自身 headers 服务（teacher-portraits 7 天）。
- 问题 ①：54px 头像仍需从 256/1254 大图在首次请求时解码，浪费生成期 CPU/内存；
- 问题 ②：`minimumCacheTTL=86400`（1 天）对静态头像、海报偏短，重复访问仍会回源校验；
- 问题 ③：`home.html` / `about.html` 静态 HTML **完全不经优化器**，直出文件，无 srcset、无格式协商；
- 问题 ④：services 1122–1491px 源图对 351px 移动档仍偏大，当前靠优化器现场降采样。
- 建议（规划项，不在本轮执行）：评估把静态 HTML 的关键海报也纳入衍生物预生成；静态头像/海报的变体缓存 TTL 上调；确认 AVIF 目标浏览器兼容矩阵。

### 5.1 设计约束

1. **原图归档不删**：校验通过后原图移入 `public/_originals/<镜像相对路径>`（或对象存储桶），`manifest.json` 记录 `原路径 → 新路径 → 原字节 → 新字节 → 双 sha256`。
2. **幂等**：manifest 已记录且衍生物存在、sha256 一致则跳过；重复运行不重复转码、不重复归档。
3. **逐张校验**：尺寸 = 目标档；`PIL ImageChops.difference` 平均误差 ≤ 阈值（RGB 建议 ≤6/255）；alpha 通道存在性与模式一致；GIF 核对帧数与时长。
4. **失败不动原图**：任一校验失败，记录到 `report.json` 的 `failed` 列表，保留原图与原引用，继续下一张。
5. **产出 `report.json` 供人工抽查**：`converted / skipped / failed` 三组，含前后字节、误差指标、待人工复核清单。
6. **默认 dry-run**：不加 `--apply` 只打印计划与预估收益，不写盘；先在目录副本上演练。
