# edu-manage 阿里云预构建部署说明

本文记录 2026-09-01 已实际验证成功的生产部署方式。日常部署只向阿里云 Workbench 上传一个 `.tar` 总包；服务器不再执行 `npm install`、`npm run build` 或 `prisma db push`。

## 一、部署方式说明

本机通过 Docker 的 Linux Node 22 环境完成：

1. 安装锁定依赖；
2. 生成 Prisma Client；
3. 执行 Next.js 生产构建；
4. 在 Linux 容器内启动 `/login` 冒烟检查；
5. 生成可直接运行的 `tar.gz` 和 SHA256；
6. 再把运行包、SHA256 和部署脚本合并成一个方便 Workbench 上传的 `.tar` 总包。

当前机器使用 Docker Desktop 4.69.0。Windows Insider Build 26200 与较新 Docker Desktop 存在 AF_UNIX socket 兼容问题，在问题解决前不要随意升级 Docker Desktop。

预构建包通常约 70–80 MB。它比以前约 20 MB 的源码包大，是因为已经包含 Linux 生产依赖、Next.js 构建产物和 Prisma 迁移工具；服务器不需要再次下载依赖和编译。

## 二、本机生成 Linux 运行包

启动 Docker Desktop，在 PowerShell 中执行：

```powershell
cd "D:\01muzhexuetang\muzhexuetang\coding\edu-manage"
powershell -ExecutionPolicy Bypass -File scripts\build-linux-release.ps1 -Registry https://registry.npmmirror.com
```

构建成功后，`release` 目录会生成：

```text
edu-manage-runtime-YYYYMMDD-HHMM.tar.gz
edu-manage-runtime-YYYYMMDD-HHMM.tar.gz.sha256
```

脚本只有在 Linux 容器内的 `/login` 冒烟检查通过后才会输出运行包。本机默认仅保留最近两个完整运行包。

## 三、生成单文件 Workbench 上传包

将下面命令中的时间戳替换为本次运行包的实际时间戳：

```powershell
tar -cf release\edu-manage-deploy-YYYYMMDD-HHMM.tar `
  -C release `
  edu-manage-runtime-YYYYMMDD-HHMM.tar.gz `
  edu-manage-runtime-YYYYMMDD-HHMM.tar.gz.sha256 `
  -C .. `
  scripts/deploy-prebuilt-tar.sh
```

检查总包内容：

```powershell
tar -tf release\edu-manage-deploy-YYYYMMDD-HHMM.tar
```

正确的总包只应包含：

```text
edu-manage-runtime-YYYYMMDD-HHMM.tar.gz
edu-manage-runtime-YYYYMMDD-HHMM.tar.gz.sha256
scripts/deploy-prebuilt-tar.sh
```

不要把 `.env`、源码目录、`node_modules`、`.git`、日志、数据库文件、旧压缩包或服务器上传资料额外放进总包。

## 四、通过阿里云 Workbench 上传

在阿里云 ECS Workbench 中，将下面这个单文件上传到服务器 `/tmp/`：

```text
release/edu-manage-deploy-YYYYMMDD-HHMM.tar
```

服务器进入 `/tmp` 并解开外层总包：

```bash
cd /tmp
tar -xf edu-manage-deploy-YYYYMMDD-HHMM.tar
```

## 五、首次切换到版本化部署

首次使用此流程时，先安装总包里的最新版部署脚本：

```bash
cd /opt/edu-manage
mkdir -p scripts
install -m 755 /tmp/scripts/deploy-prebuilt-tar.sh scripts/deploy-prebuilt-tar.sh
```

### 1. 兼容旧版 UPLOAD_DIR

如果生产 `.env` 中配置了：

```text
UPLOAD_DIR=/opt/edu-manage/uploads
```

则建立到新版共享上传目录的兼容链接：

```bash
cd /opt/edu-manage

test -d shared/public/uploads || {
  echo "共享上传目录不存在，请停止部署"
  exit 1
}

if [ ! -e uploads ] && [ ! -L uploads ]; then
  ln -s /opt/edu-manage/shared/public/uploads uploads
fi

readlink -f uploads
```

最后一条命令应输出：

```text
/opt/edu-manage/shared/public/uploads
```

这个链接不会删除或覆盖上传文件。

### 2. 执行部署

整条命令放在一行执行，避免复制时混入多余的反斜杠或 HTML 空格：

```bash
bash /opt/edu-manage/scripts/deploy-prebuilt-tar.sh /tmp/edu-manage-runtime-YYYYMMDD-HHMM.tar.gz
```

部署脚本会自动执行：

1. 压缩包完整性和 SHA256 校验；
2. 生产环境与数据库连接预检；
3. 初中、高中 PostgreSQL 数据库备份；
4. Prisma migration；
5. 在 3100 候选端口启动并健康检查；
6. 健康后切换 `current` 和 PM2；
7. 正式端口健康检查；
8. 保留最近五个服务器版本。

候选版本检查失败时不会停止旧版本；正式切换失败时脚本会尝试恢复旧版本。数据库迁移不会自动回退，因此生产迁移必须保持向后兼容。

## 六、Nginx 静态资源兼容

如果部署后网页只显示一行未排版文字或页脚，说明 HTML 已返回，但 CSS/JavaScript 静态资源仍被 Nginx 从旧目录 `/opt/edu-manage/.next/static` 读取。

执行一次兼容处理：

```bash
cd /opt/edu-manage

if [ -d .next ] && [ ! -L .next ]; then
  mv .next ".next.before-versioned-$(date +%Y%m%d-%H%M%S)"
fi

ln -sfn /opt/edu-manage/current/.next /opt/edu-manage/.next
nginx -t && systemctl reload nginx
```

完成后在浏览器按 `Ctrl + F5` 强制刷新。这个 `.next` 链接始终跟随 `current`，以后切换版本不需要重复建立。

## 七、日常后续部署

首次兼容处理完成后，日常部署只需：

1. 本机构建新运行包；
2. 生成并上传一个 `.tar` 总包；
3. 在服务器解开总包；
4. 更新部署脚本并运行部署命令。

服务器命令模板：

```bash
cd /tmp
tar -xf edu-manage-deploy-YYYYMMDD-HHMM.tar

cd /opt/edu-manage
install -m 755 /tmp/scripts/deploy-prebuilt-tar.sh scripts/deploy-prebuilt-tar.sh
bash scripts/deploy-prebuilt-tar.sh /tmp/edu-manage-runtime-YYYYMMDD-HHMM.tar.gz
```

## 八、部署完成后的检查

```bash
pm2 status edu-manage
readlink -f /opt/edu-manage/current
curl -I http://127.0.0.1:3000/login
curl -I https://muzhexuetang.xyz/login
pm2 logs edu-manage --lines 30 --nostream
```

正常结果：

- PM2 中 `edu-manage` 为 `online`；
- `current` 指向刚部署的 `releases/时间戳`；
- 登录页返回 `200`、`301`、`302` 或 `307`；
- PM2 日志没有持续重启或未捕获异常。

健康检查过程中偶尔先出现一次 `curl: (7) Failed to connect`，随后显示“健康检查通过”，通常只是 Node 服务尚在启动，不属于最终部署失败。

## 九、服务器目录约定

```text
/opt/edu-manage/
├── current -> releases/当前版本
├── releases/                 # 不可变程序版本，保留最近五个
├── shared/
│   ├── .env                  # 生产配置，不进入发布包
│   └── public/
│       ├── uploads/
│       ├── services/
│       ├── marketing/
│       ├── business-assets/
│       └── volunteer/docs/
├── uploads -> shared/public/uploads
├── .next -> current/.next    # 兼容旧 Nginx 静态资源路径
└── scripts/
    └── deploy-prebuilt-tar.sh
```

`shared/.env` 和 `shared/public` 是生产持久数据，不能通过发布包覆盖或删除。
