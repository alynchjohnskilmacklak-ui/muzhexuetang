# 晚托与周末作业班实施口径

本文记录 2026-08-16 对外部修改建议的复核结论和当前实现，作为后续维护依据。

## 已采纳

- 作业班使用独立班级容器，不复用课程、课次、教室、课时或工资模型。
- 一个班可有多名在任教师；更换教师时结束旧任期并新增任期，不删除历史。
- 晚托只允许周一至周五按天考勤；周末班只允许周六、周日按自定义时段考勤。
- 作业、状态、老师说明、照片和到离校信息通过 `Notification` 通知家长。
- 家长已读只使用 `Notification.read/readAt`，不增加作业班专用已读字段。
- 旧 `StudyHallPlan/StudyHallRecord` 暂时保留，迁移时按运营期和负责教师归并为班级。

## 对原建议的必要修正

1. 不直接维护 `remainDays -= 1`。月度剩余天数由“月度应到额度 + 人工调整 - 当月不同日期的实际到勤数”动态计算，因此重复提交、撤销误登记和并发重试都不会造成额度漂移。
2. 不使用 nullable `sessionId` 参与唯一约束。晚托使用非空键 `DAY`，周末使用 `SESSION:<id>`，数据库唯一约束为 `(classRecordId, studentId, attendanceKey)`。
3. 教师任期不使用 `(classId, teacherId)` 普通唯一约束，否则同一教师离开后无法再次任教。数据库只约束同一教师在同一班最多有一个“在任”记录。
4. 作业通知按“家长 + 类型 + 作业条目”建立部分唯一索引。重复保存会更新同一通知并重新置为未读，不制造重复通知。
5. `unread-counts.notifications` 已包含作业通知。接口另返回 `studyHallHomework` 仅供作业班菜单显示分类红点，顶栏总数不再重复相加。
6. WxPusher 网络请求不放在数据库事务中。事务先原子保存作业和站内通知，提交后再推送并回写 `pushStatus`，避免外部网络延迟锁住数据库事务。

## 月度额度

- 默认额度按运营期范围、入班日、离班日和班级上课日实时计算。
- 后进学员从实际入班日开始计算。
- 晚托默认排除周六、周日；当前口径不自动排除法定节假日，如需排除应先接入校历表。
- `StudyHallMonthlyQuota` 用于锁定某月额度或记录人工调整；没有覆盖记录时使用动态默认值。
- 周末班本轮只做分段考勤，不计算收费额度，等待收费口径确定。

## API

- `GET /api/study-hall?date=YYYY-MM-DD&termId=...`：管理员或教师读取班级、当日记录和晚托月度余额。
- `POST /api/study-hall`：管理员新建班级、教师、成员和周末时段。
- `PUT /api/study-hall`：管理员更新班级；教师更换和成员离班保留历史。
- `PATCH /api/study-hall`：管理员或在任教师登记一名学员当天/时段的作业和考勤，并同步家长通知。
- `GET /api/parent/study-hall`：家长读取已绑定学员的作业班记录。
- `PATCH /api/parent/study-hall`：家长打开深链时将对应通知标记已读。
