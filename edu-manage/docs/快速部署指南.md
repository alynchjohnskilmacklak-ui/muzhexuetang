## 加速原理

- 引擎数据盘在 D 盘 → 镜像层缓存、npm 依赖层缓存重启后保留。
- 只改业务代码时，使用持久 `mzt-release` 构建器运行 `docker buildx build --builder mzt-release`，base/deps 层直接命中缓存，**只需重新编译 Next.js（约 8-12 分钟）**，不需要重新 `npm ci`。
- 部署脚本会把 `docker save` 产生的镜像流用最快级别 gzip 无损压缩后上传；若压缩反而增大文件则自动保留原 tar。服务器流式交给 `docker load`，不会再额外写一份未压缩副本。

## 一条命令部署（每次约 15 分钟）

### 1. 启动 Docker Desktop 并等引擎
```powershell
Start-Process "C:\Users\Administrator\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe"
$docker = "C:\Users\Administrator\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe"
& $docker version --format "{{.Server.Version}}"   # 返回 29.4.0 即就绪
```
> 注意：引擎偶尔启动即退出，若断连就重新 Start-Process 一次；构建期间勿关闭 Docker Desktop。

### 2. 构建、上传、切换和清理
```powershell
cd "D:\01muzhexuetang\muzhexuetang\coding\edu-manage"
./scripts/deploy-compose-image.ps1 -VersionTag fix-v4-<日期>
```

脚本会复用本地依赖和构建缓存，生成并压缩镜像包、校验 SHA256、上传并切换 Compose 服务。日志会分别显示构建、导出压缩、上传、远端加载切换的耗时及压缩前后体积，便于确认真正耗时的阶段。服务器只在切换期间临时保留旧镜像用于自动回退，健康检查通过后删除旧应用镜像标签和上传包，只保留 `edu-manage-app:latest`。本地同样只保留一个 `edu-manage-app` 标签，构建缓存保留以加快下一次构建。数据库和 `/data/backups/edu-manage` 不会被清理或修改。

### 5. 验证
```powershell
curl.exe -s -o NUL -w "HTTP %{http_code}" https://muzhexuetang.xyz/
# 业务修复验证：镜像内检索编译产物特征字符串
docker run --rm --entrypoint sh edu-manage-app:latest -c "grep -rl '<修复文案>' /app/.next | head -2"
```

## 部署完成后的回滚

部署期间会自动保留旧镜像，健康检查失败会自动回退。部署成功后按“只留一个镜像”的策略清除旧应用镜像；如需之后回到旧代码，需要从源码重新构建并部署。数据库备份仍独立保留。

## 常见坑
1. **不要手工再次打包镜像**：部署脚本会生成 gzip 压缩的 Docker save 数据流，服务器会流式解压后交给 `docker load`；不要再用 Windows tar 把生成的文件包一层。
2. **PowerShell 转义**：远程命令含引号时用 paramiko/Python 脚本执行，避免 PowerShell 解析 `\"` 和 `|`。
3. **Docker 引擎闪退**：启动后 1-2 分钟内再次 `docker version` 确认；构建放后台并写日志文件。
4. **注释不入产物**：镜像内验证特征用 JSX 文案 / 字符串字面量（如"仅展示本月有课时的同学"），不要用代码注释。
