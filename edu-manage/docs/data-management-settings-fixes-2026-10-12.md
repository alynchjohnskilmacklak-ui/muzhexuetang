# 数据管理与系统设置：本轮修改记录

## 范围与操作边界

本轮只修改本地代码，并运行类型检查、静态检查和使用模拟依赖的自动化测试。没有连接正式数据库执行删除、恢复、清理或配置修改，也没有部署到服务器。

审查依据：`docs/data-management-settings-audit-2026-10-12.md`。

## 入口与功能整理

- 数据管理默认进入「数据健康」，原来横向铺开的 14 个入口改为四组选择：诊断与维护、人员与报名、课程与教学、通知与服务。保留全部诊断模块，并提供回收站、系统设置和对应业务管理的跳转。
- 系统设置分为基础设置、账号与安全、消息与权益、审计与导出。手机采用分组下拉选择，桌面采用分组菜单。
- 教师账号、家长账号并入「账号与绑定」。原来的 `?tab=teacher-accounts`、`?tab=parent-accounts` 链接仍能进入对应角色。
- 已打开的设置栏目保持挂载，切换栏目不清空表单。权益文案的后台重新拉取不会覆盖正在输入的内容。刷新或离开页面仍需要先保存。

## 数据可靠性

- 单条、批量删除/恢复共用回收站服务；不再单纯改一个状态字段。
- 批量操作返回成功 ID、失败 ID 与原因，只保留失败项供重试。批量删除增加确认提示。
- 普通取消、归档、离职与真正进入回收站区分开来；没有删除批次的历史记录不能在底层被直接恢复成有效状态。
- 并发删除/恢复使用条件更新领取记录，避免重复创建删除批次；恢复旧批次不能覆盖后来的删除批次。关联数据按原删除批次恢复。
- 删除一个孩子时，家长还有其他有效孩子则不暂停家长账号；保留原主教师和离开时间以便恢复。
- 通用编辑器仅开放安全资料、备注修正。考勤扣费、课次调整、反馈发布、报名课时等关键字段回到业务流程，不允许通过底层编辑绕过。
- 年份转为数字并校验；拒绝非法字段、对象冒充文本、过长内容和非法请求体。通用资料更新与操作日志一起提交。
- 单条访问、更新、删除、恢复和批量操作校验当前登录学部。课时调整限定为报名操作，学生也必须属于当前学部。
- 数据概览补上日期上界与软删除过滤。健康检查按学部筛选，并区分真实异常总数与最多 50 条展示样本。

## 设置、账号与反馈提示

- 教室、费用类型、学科、机构资料、权益文案、操作日志与账号列表补齐失败/重试状态；保存失败不关闭输入窗口或显示成功。
- 设置保存过程有加载状态，避免连续提交；学科拖动排序失败会重新读取真实顺序。
- 学科标签颜色提交为字符串，编辑与删除使用独立按钮，避免把关闭图标误当编辑操作。
- 学科改名检查课程、教师、课次、报名、试卷、资料引用，已有业务引用时禁止直接改名。
- 统一账号列表优先按 `teacherId` 关联教师，不再靠同名教师匹配账号；家长列表兼容两种已有绑定字段，不展示已软删除的学员。
- Logo 上传与表单字段分开，上传失败或没有图片地址会提示；兼容旧上传路径。机构资料注明其生效边界，避免误以为保存后自动替换全站品牌。
- 原权限开关、通知开关没有业务消费链路，本轮改为规则说明，接口拒绝继续写入无效开关。没有改变实际权限与通知流程，也没有声称已接入动态权限配置。

## 导出、清理与恢复

- JSON 明确为有限的业务数据导出，不是可还原数据库备份；保留既有导出能力并注明范围限制。下载前校验 HTTP 状态。
- 真实备份与恢复集中到数据管理；清理入口指向回收站。兼容清理 API 只处理到期的回收站记录，不再按归档/取消/离职状态硬删除业务数据。
- 双学部恢复在覆盖前检查两份备份、数据库配置和归档可读性，拒绝两个学部指向同一个目标库。
- `pg_restore` 增加单事务与遇错退出选项，单库恢复失败回滚；双库分别提交，明确显示完成与失败学部。
- 恢复日志写入失败与恢复本身失败分开报告。网络中断提示先核对服务器结果，不要直接重复恢复。
- 恢复入口明确说明：不自动还原上传附件，两个数据库不具备共同事务。正式恢复前仍须创建新备份、进入维护窗口，并在隔离环境演练。
