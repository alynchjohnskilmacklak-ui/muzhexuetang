# 学习情况统计中心设计

## 意图

将管理端现有“错题与题库统计”扩展为统一的学习情况统计入口。管理员进入 `/grades` 后先选择“题库练习”或“单词背诵”，再进入各自独立的统计页面；后续可在同一选择页增加其他学习模块。

## 目标

- 菜单名称调整为“学习情况统计”，入口 `/grades` 展示模块选择页。
- 将现有题库练习统计页面迁至 `/grades/practice`，保留当前筛选、排行榜、学员详情和练习记录行为。
- 新增 `/grades/vocabulary`，展示家长端背词练习产生的学习情况。
- 背词总览支持按年级、教材册次和学生姓名筛选；学员详情展示单元掌握情况与最近练习记录。
- 复用现有 `VocabProgress` 和 `VocabSession` 数据，不重复存储、不重置已有数据。

## 非目标

- 不改变家长端背词出题、判分、复习或学习记录写入流程。
- 首版不提供逐词全量清单、导出、教师端视图或新的学习行为。
- 不新增 Prisma 模型或数据库迁移。

## 方案

- **统一选择页 + 独立子页面（选定）**：`/grades` 做入口选择；题库练习与单词背诵分别使用 `/grades/practice`、`/grades/vocabulary`。符合“先选择、再进入”的目标，并为后续模块留扩展位。
- **在旧统计页增加页签**：代码移动少，但选择和统计内容混在同一长页，不符合先选后进入的交互。
- **拆成两个菜单入口**：各页面直达，但绕过统一选择页，也会让后续模块继续增加导航项。

## 数据与权限约束

- 背词练习已由 `/api/parent/vocab/session` 在事务中写入 `VocabSession`，并按学生和单词更新 `VocabProgress`；新统计只读取这两张表。
- 新管理端接口使用 `requireAdminUser()`，所有学生、练习记录与进度查询均限制在当前管理员 division；学员详情接口必须再次验证学员属于当前 division 且未软删除。
- 同一学生可能因学期产生多个学籍记录；总览先用 `identityId` 在当前 division 内选当前有效代表，再将同 division、未软删除的历史记录纳入该代表的 session/progress 汇总。停用与离校记录不可作为当前代表或详情入口。
- “练习学员”仅统计当前筛选下至少有一条 `VocabSession` 的身份；只有进度记录的身份仍可在列表查看进度，但不计为完成练习的人数。
- 总览掌握数来自按身份去重后的 `VocabProgress.status`，练习正确率按已保存 session 的 `correct / total` 汇总；单元汇总按身份、教材年级、册次和单元分组，避免不同教材中同名单元合并。
- API 使用 `private, no-store` 响应头，不返回电话等与学习统计无关的个人信息。

## 实施约定

- `src/app/(main)/grades/page.tsx` 改为选择页；旧题库统计页面整体迁至 `src/app/(main)/grades/practice/page.tsx`，仅调整返回入口和页面标题。
- 新增背词统计页面与 division-scoped 总览/学员详情 API。总览按显式 `identityId` 归并同一 division 的学期学籍记录，字段包含有 session 的练习学员数、练习次数、去重后的单词进度数、已掌握词数和汇总正确率；学员详情按教材年级、册次、单元显示 `MASTERED / LEARNING / WRONG` 分布及最近 session。
- 入口页以可配置的模块卡片呈现“题库练习”和“单词背诵”；卡片点击导航到对应路由，子页提供返回统计中心的入口。
- 桌面和移动端共用 `admin-nav.tsx`，将菜单标签改为“学习情况统计”，菜单仍指向 `/grades`。
- 沿用管理端当前页面框架、暖光主题和全局按压反馈，不新建平行动效；无记录、加载和接口错误分别显示可理解状态。

## 验收

- 从管理端菜单进入 `/grades` 可看到两个入口；点击后分别进入题库练习统计和单词背诵统计，返回动作回到选择页。
- 原题库统计的筛选、排行榜和学员详情仍可通过 `/grades/practice` 使用。
- 背词统计能正确显示已产生的数据；新练习完成后刷新页面可看到更新。
- 不同 division 的管理员不能读取其他 division 学员的背词汇总或详情。
- 改动文件通过 ESLint；TypeScript 检查和生产构建结果如实记录。按项目约束，本批不新增或运行测试。
