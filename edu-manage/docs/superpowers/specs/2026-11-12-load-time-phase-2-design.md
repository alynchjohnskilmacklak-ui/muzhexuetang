# 加载优化第二批设计

## 目标

优先减少家长练习页、反馈页和 AI 页面首次使用时需要下载或处理的资源，同时保留题图清晰度、授权边界、API 现有字段语义与图片源文件。

## 已确认的现状

- `src/app/globals.css` 原始体积约 369 KB，gzip 后约 59 KB；全量拆 CSS 风险高，当前压缩传输体积不是首要瓶颈。
- 首页横幅、登录轮播已使用 Next Image；横幅同时用于 Open Graph，原始 PNG 应保留。
- 练习题通过原生 `<img>` 直接加载图片。20 张超过 100 KB 的题图中，19 张可用无损 WebP 减少体积；原 PNG 保留，题目仅切换 `imageUrl` 到 WebP。实际这 19 张 PNG 共 7,321,036 bytes，WebP 共 3,395,250 bytes，减少 3,925,786 bytes（53.6%）。
- 1,254×1,254 的小校徽 PNG 被几处原生图片和 CSS 水印直接使用；这些展示位改用专用 128×128 WebP。
- KaTeX CSS 在根布局全站加载，但实际渲染点集中在 AI 对话和数学文本组件。
- `/api/feedback` 的查询包含整条课次与班级记录；调用方只依赖其中少量字段。`/api/dashboard` 把两次课次明细查询拉回后再按月份计算课时。

## 方案与取舍

1. **题图继续使用原 PNG**：兼容性最好，但题目练习仍按原尺寸传输。放弃。
2. **转成有损 WebP/AVIF**：节省更多，但考试题图含文字与图表，存在边缘失真风险。放弃。
3. **无损 WebP + 原图保留，并只改已核对的静态 `imageUrl`**：图片像素不变，现代 Android/华为浏览器可直接加载，源文件仍可回退。采用此方案。

接口方面只裁剪反馈接口的关联记录字段，保留根反馈字段和授权判断所需字段；看板课时改为数据库按月份聚合，SQL 逐项复用当前学期/校区、可见班级与课程、课次状态及班级/课程软删除条件。全局 CSS 不做大规模搬迁，只把 KaTeX 样式放到实际使用它的模块。

## 范围与边界

- 不删除或覆盖 PNG/GIF 母版，不改变练习题文字、答案或图片含义。
- 不改图片上传/OSS 路径，不缓存个人数据，不改 API 响应的已使用字段。
- 不做全局 CSS 大重构，不改 Nginx/CDN，不跑生产构建或测试套件。
- `next/image` 已优化的首页横幅和登录轮播不重复转码；旧贴纸 GIF 无代码引用，贴纸运行时已使用 WebP。

## 验收

- 所有切换路径的题图都存在，PNG 原件仍保留，WebP 为无损格式。
- 小校徽 CSS 与页面引用都指向 128×128 WebP。
- 根布局不再全站引入 KaTeX CSS，AI/数学渲染仍各自加载样式。
- 反馈授权字段和前端使用字段未丢；看板月度课时聚合遵循原筛选与计算规则。
- TypeScript 与 ESLint 检查结果明确记录；不运行测试或生产构建。
