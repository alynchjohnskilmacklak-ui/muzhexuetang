# 教师端审计优先项实施计划

> 执行方式：当前会话由主智能体按任务顺序原地实施；每个任务先补失败测试，再做最小实现。

**目标：** 收紧教师端反馈图片授权、补教师系统提醒及真实角标、让学习目标可软删除，并阻止空名单课次误提交考勤，同时清楚区分历史趋势和当前学员范围。

**架构：** 复用现有教师身份校验、Notification/TeacherMessage、`deletedAt` 和空态组件；不新增依赖、不改数据库结构、不批量改历史数据。教师端不读取家长满意度评价或理由；普通班排课继续只读，不授予教师直接改课权限。

**技术栈：** Next.js App Router、TypeScript、Prisma、Vitest、Ant Design/SWR。

## Approaches

- **新建独立教师通知系统：** 新建导航和存储，范围大且重复现有表；不采用。
- **复用现有消息页和两张提醒表：** `TeacherMessage` + 当前用户自己的 `Notification` 一起呈现，角标据未读数计算；采用此方案。
- **直接自动补齐所有空名单：** 会把不匹配科目的学员加入课次；不采用，只修新写入已具备的科目快照链路的保护与教师空态。

## 范围与约束

- `ARCHIVED` 表示历史反馈归档，不能等同 `REVOKED`；不回收已获得的历史教师奖励。明确撤销继续走已有冲销链路，不回写历史账务。
- 当前学员列表仍排除停用/软删除学员；历史出勤趋势保留过去教学记录，并标明口径。
- 不把家长满意度、理由、管理审核结果展示给教师。
- 新报名和课表生成已按报名科目写名单快照；科目不匹配的旧课次只提示管理端核对，不自动补人。
- 不执行生产或本地数据库迁移、账务修正、名单批量回填。

## 任务

### 1. 反馈图片授权跟随反馈状态

**文件：** `src/lib/classroom-feedback/access.ts`、`src/lib/classroom-feedback/access.test.ts`

- 增加 `deletedAt` 状态判断：教师只能看本人未软删除且未归档/撤销的反馈图片；家长只看未软删除的已发布反馈；管理员仍保留审计查看权限。
- 保留教师查看自己草稿的行为，避免破坏编辑流程。
- 测试本人草稿可见、已归档/已撤销/软删除不可见、家长软删除不可见、管理员审计仍可见。

### 2. 教师消息页接入系统通知并修正角标

**文件：** `src/app/api/teacher/messages/route.ts`、复用 `src/app/api/teacher/messages/[id]/read/route.ts`、`src/app/api/teacher/dashboard/route.ts`、`src/app/teacher/messages/client.tsx`、教师端导航/相关测试。

- 消息 API 按当前教师读取本人 `TeacherMessage` 和 `userId` 匹配的有效 `Notification`；只返回必要展示字段。
- 通知已读更新必须同时匹配当前用户、未删除和有效状态。
- 工作台角标统计本人未读教师消息与非家长会话通知；家长会话未读由现有会话计数提供，合并时避免重复计数，不读取满意度评价表。
- 在现有消息页增加“系统提醒”区；标记已读后刷新列表与角标。
- 测试跨教师读取/已读被拒、通知筛选和未读角标数量。

### 3. 学习目标使用软删除

**文件：** `src/app/api/teacher/learning-goals/route.ts`、`src/app/api/teacher/students/[id]/context/route.ts`、`src/lib/student-profile.ts` 与对应测试。

- DELETE 条件更新 `deletedAt` 和 `deletionBatchId`，不物理删除；重复删除返回不存在。
- GET/PATCH、教师 AI 上下文、成长档案读取均排除软删除目标。

### 4. 空名单课次安全提示

**文件：** `src/app/teacher/attendance/page.tsx` 与相关页面测试。

- 名单为空时明确提示教师联系管理端核对课次科目和有效报名；教师不能自行补名单。
- 空名单时禁用一键全勤与提交考勤，提交函数也做防守校验。
- 不改变排课、报名、科目匹配或课时规则。

### 5. 区分历史出勤趋势与当前学员

**文件：** `src/app/teacher/dashboard/page.tsx` 与相关页面测试。

- 历史图表数据继续保留历史教学记录；标题/辅助说明注明离班学员历史数据可能包含在内。
- 当前学员列表沿用现有有效学员过滤。

## 验证

- 逐项运行新增/修改的 Vitest 文件，确认测试先红后绿。
- 运行 `npx tsc --noEmit` 和改动文件 ESLint。
- 跑完整 `npm test` 回归；不运行生产迁移或历史数据写入。
