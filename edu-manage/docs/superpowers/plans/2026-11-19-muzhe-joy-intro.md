# Muzhe Joy 登录开场最终方案

用户最终选择保留「彩色手写 Muzhe Joy」，要求英文字母更清楚。时长 7 秒，随后出现提供的牧哲校徽，向外展开进入登录页。

- 英文用自绘 SVG 连笔路径，词内连续书写，两个单词明确留空。
- M 采用清楚的大写结构，z 保留平直横笔与斜笔并去掉下方回环，J 明确起笔与下弯，保留可辨认的 o / e 内白和 y 下伸笔。
- 线宽由 3.4 调到 3.8；完整文字在时间轴 52% 写完，保留到 64% 再退出，停留约 0.84 秒。
- 文字收笔后衔接流线、彩色轮廓、牧哲 Logo 及展开转场；不改变 7 秒总长。
- 背景按用户后续要求改为贴合校徽的暖白底：左上淡橙、右下淡青绿，中间柔和纸白光，底部两条书页弧线。全部背景装饰放在同一个展开遮罩内，转场不会遗留遮挡层；首次加载占位背景也同步变暖。
- 手写彩色线条调整为浅底适用的深一档配色，六个主要色值在暖白底上的对比度约 4.0–4.5:1。校徽保留原有橙、青绿并放大居中，下面是「牧哲学堂」和既有校训「不怕学浅，唯恐志短」，手机端同样居中排布。
- 用户要求跳过按钮明显：右上角为 132×48px 起的「跳过动画」按钮，橙色实底、深色文字、深橙 2px 描边、15px 加粗标签及 18px 箭头，整个开场期间保持可见。保留原有点击后 180ms 退出、计时器清理及仅完成一次的逻辑。
- 保留跳过、自动完成和减少动态效果。每次进入 `/login` 都播放开场，旧的 `muzhe-login-splash-seen-*` 标记不再参与判断；在当前登录页填写或提交账号不会重新播放。`/login?intro=preview` 仍可访问，但播放不依赖预览参数。

当前实现文件：`src/components/EnglishIntroWord.tsx`、`SplashScreen.tsx`、`SplashScreen.module.css`；中文变体不再被开场组件引用。

验证：英文与开场组件定向 TypeScript 检查通过，ESLint 无问题，登录流程 12 项回归通过，本地预览 HTTP 200。由相同矢量路径导出的最终完整字形已目视核对。浏览器控制未暴露预览标签页，因此不声称已经完成完整浏览器逐帧复核。未部署。

明显跳过按钮改动后重复验证：定向 TypeScript、ESLint、12 项登录流程回归均通过；预览 HTTP 200。跳过按钮不再跟随旧时间轴降低透明度或提前淡出。

录屏缺陷修复：用户从首页点击「进入系统」只短暂黑屏就出现表单。逐帧检查录屏并追踪登录页条件，发现旧版永久 seen 标记会在预览时写入，之后普通入口不挂载 SplashScreen。已删除读写此标记的整个门控，每次页面挂载都启动开场。回归契约先观察到 11 通过、1 失败，再修复至登录、账号记忆和鉴权共 26 项通过；定向类型检查通过，ESLint 无错误（登录页 4 条原有未使用变量警告），普通 `/login` HTTP 200。原生浏览器验证受窗口控制中断限制，未声称完成实际逐帧播放验收。
