# 管理端管控传导报告：优先代码收尾计划

## 目标

围绕报告中可由代码直接处理且已确认的事项，修复家长通知的当前绑定范围、让教师看到自己的当前工资规则、提供未来空课次名单的安全核查/补录流程，以及提供学生余额快照与报名台账的只读对账报告。

## 全局约束

- 不改生产或本地业务数据库中的历史账务；不运行 `--apply`、迁移或部署。
- 家长通知只允许展示无学员归属的通用通知，或当前仍绑定给该账号的有效学员通知；列表、详情、未读数和已读写入必须使用同一范围。
- 课次点名继续以 `ClassLessonStudent` 为来源。只核查/补录未来、未取消、未删除、未提交考勤、无考勤记录且无名单快照的课次；按有效报名学科匹配，默认只读，显式 `--apply` 才写。
- 教师工资页面只展示当前教师自己的有效工资配置，并明确历史流水金额不因当前配置而重算。
- 余额核对只读、默认执行，不提供隐式写入选项。

## Task 1 — 家长通知绑定范围

**接口：** `business-visibility.ts` 提供统一父级通知范围；家长通知列表、详情、未读计数、单条/批量已读、汇总角标都消费该范围。学生相关的今日/周报通知继续绑定当前 `studentIds`。

**TDD：** 先写 helper 与 API 回归测试，证明另一名家长的孩子通知被排除、通用通知与当前孩子通知保留；验证读操作不会修改被排除通知。

**验证：** 运行新增与受影响通知路由测试、类型检查。

## Task 2 — 未来空名单课次核查与受限补录

**接口：** 新增纯函数规划模块和 CLI。只选择今天及之后、`SCHEDULED`、没有名单快照、没有考勤/考勤提交、班级有效的课次；用有效报名及课次学科计算候选名单。CLI 默认 dry-run，`--apply` 才按课次事务性 `createMany(skipDuplicates)`。历史课次不参与。

**TDD：** 先测试候选范围、学科过滤、无合格报名、已有快照/考勤/已提交/历史/取消课次均不补录。另核实学科修改查询只查当前学员名单行，避免把正确代码改坏。

**验证：** 运行纯函数测试及相关课次创建/报名测试。CLI 仅允许尝试只读 dry-run；若本地 DB 不可达，报告准确命令与期望输出供用户或其他 agent 执行。不得执行 `--apply`。

## Task 3 — 教师端显示当前工资规则

**接口：** 教师薪资 API 返回当前教师配置（包含默认回退值）；页面展示班课、一对一、反馈奖励当前费率，并说明历史明细按已生成流水金额结算。

**TDD：** 先为薪资 API 增加测试，验证自定义费率由当前教师记录返回且不查询他人；验证无配置时显示系统默认值。

**验证：** API 测试、薪资 UI 类型检查及 ESLint。

## Task 4 — 只读余额快照对账

**接口：** 新增纯计算函数与 CLI，按系统当前有效报名范围汇总 `Enrollment.totalHours/remainHours`，与 `Student` 快照逐人比较；列出差异及计数，不包含写库逻辑。

**TDD：** 先测试一致、缺失报名聚合、浮点容差和差异分类。

**验证：** 纯函数测试；尝试运行数据库只读报告。连接失败则不判为业务验证通过，并提供其他 agent 可执行的步骤。

## 最终验证

完成所有任务后运行相关测试合集、`npm run type-check`、必要的 ESLint 检查；检查修改文件及 diff。不得部署或写库。
