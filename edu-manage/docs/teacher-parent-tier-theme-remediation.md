# 教师与家长等级主题：代码审查及修改指令

> 2026-10-06 · 交付给实施 Agent 的设计与验收文档。本轮只审查代码并提出方案，**尚未修改页面、构建或部署**。实施前先阅读仓库 `AGENTS.md`、`DESIGN.md`、`docs/frontend-rules.md`；如涉及上线，再阅读 `docs/production-safety.md`。

## 1. 目标与边界

教师五档（管理、专属、资深、经验、新晋）和家长三档（普通、VIP、SVIP）要有可辨识的气质，但仍是一套牧哲学堂产品。等级不应把表单、数据卡和文章变成八套互不兼容的页面。**主题决定外层氛围；每块内容表面决定自己的文字颜色。** 深墨绿可用于专属教师/SVIP 的导航、HERO、权益卡，不应靠全局把所有文字涂浅色。

保留现有大按钮、大卡片、宽松留白和移动端优先的交互尺度。不要缩小触控区、盲目加金色渐变、闪烁动效或在长篇反馈正文后铺深色底。管理端保持现有暖浅色设计；管理端查看的教师/会员等级徽标可以按相应等级显示，不让管理端整页跟随某个对象变色。

## 3. 主题的视觉方案

### 3.1 固定的表面层级

| 层级 | 用途 | 背景 | 默认文字与规则 |
| --- | --- | --- | --- |
| 页面画布 `canvas` | 页面空白区、卡片之间 | 按等级轻微染色；SVIP/专属也以柔和暖米色为主要阅读画布，深色只在顶部形成身份氛围 | 深墨色；页面标题不能因为上方 HERO 深色而变成浅字 |
| 内容大卡 `surface` | 课表、考勤、反馈、学生信息、教师资料、表单 | `#FFFFFF`，1px 微边、14–20px 圆角 | 主字 `#1A1201`、次字 `#5B5148`；不继承外部深色主题的浅字 |
| 次级卡/内嵌指标 `surface-subtle` | 数据指标、课时格、提示条 | 米白/浅主题色 | 主次字均取深色；金色仅作装饰 |
| 深色展示面 `surface-inverse` | 专属/SVIP HERO、权益卡、选定的导航 | 墨绿、深橙或深紫 | 标题浅色、正文高对比米白，弱化文案仍需可读；内部浅卡必须重置为 `surface` 文字 |
| 浮层 `overlay` | 下拉、弹窗、抽屉、日历、Toast | 统一白/暖浅色优先 | 深字，不继承 HERO 字色；只有经过完整校验才允许深色浮层 |

这样保持“深墨绿高级感”，同时让长篇文章、反馈、表单和大卡片仍可舒适阅读。专属教师和 SVIP 同属墨绿金系，但专属教师更偏冷深松绿/职业工作台，SVIP 更偏暖墨绿/家庭陪伴，徽标形态与 HERO 文案不同；不要用背景色作为唯一等级识别信息。

### 3.2 建议的等级配色（候选，实施时须逐项测对比度）

共享：内容卡 `#FFFFFF` / 主字 `#1A1201` / 次字 `#5B5148`；大段正文不使用哑金色。下面的“深色主面”只用于 Header、HERO、权益卡或强调模块，不表示整页涂满。

| 客户端等级 | 页面画布 | 深色主面或重点色 | 其上的文字 | 浅色卡内强调文字 | 辨识语言 |
| --- | --- | --- | --- | --- | --- |
| 教师·管理 `MANAGER` | `#F0EDF8` | `#4C3FA8` | `#FFFFFF` | `#4C3FA8` | 克制紫、清晰工作台 |
| 教师·专属 `ELITE` | `#F6F2E9` | `#0E2E2A` | `#F6E9C8` | `#123C35` | 深松绿、哑金细边；金徽标用墨绿字 |
| 教师·资深 `SENIOR` | `#F8F3E7` | `#123C35` | `#F6E9C8` | `#123C35` | 暖象牙与深玉绿，少量金线 |
| 教师·经验 `EXPERIENCED` | `#FFF7F1` | `#B94F25` | `#FFFFFF` | `#9B421F` | 深陶橘；品牌橙 `#E8784A` 可作点缀，不能配普通大小白字 |
| 教师·新晋 `NEW` | `#F7FBF8` | `#2D7256` | `#FFFFFF` | `#285247` | 清新叶绿、不“低等级灰化” |
| 家长·普通 `NORMAL` | `#FAF8F5` | `#2C6E52` | `#FFFFFF` | `#285247` | 品牌暖白+柔和绿，重可用性 |
| 家长·VIP `VIP` | `#FFF7F1` | `#A9512A` | `#FFFFFF` | `#9B421F` | 温暖赭橘，突出服务但不通页橙 |
| 家长·SVIP `SVIP` | `#F6F2E9` | `#123C35` | `#F6E9C8` | `#123C35` | 墨绿+哑金，阅读区仍是浅卡 |

注意：HERO 渐变**每个端点**都要与文字达标。建议只在上述深色主面之间做低幅度渐变，不要使用现有 VIP `#E8784A→#F4AC76`、普通 `#3E8E6E→#63B494` 这种一路变浅却一直写白字的组合。光带只做纯装饰，不盖在关键数字/CTA 上。

### 3.3 大按钮、大卡片和细节的硬规则

1. **大按钮**：保留现有大尺寸与有力视觉层级。主操作建议最小高度 48px、手机宽屏可满行；只有一个主按钮，其余为次级或文字按钮。深背景上的主按钮可以用哑金底+墨绿字（SVIP/专属）、白底+深色字，或经过对比校验的深色实底+浅字。浅卡内主按钮使用各等级的**深色可读**强调色；不能把亮金/亮橙底配白字当作普通字号按钮。次级、禁用、加载、成功/失败和破坏性操作必须逐态规定前景与边界，不能只靠透明度。按钮文字不得被图标、箭头、徽标挤成截断；用户侧重“立即知道下一步”。
2. **大卡片**：维持 14–20px 圆角、舒服内边距和清晰层级。大白卡即便处在墨绿外背景也始终深字；其内部的小浅卡仍深字。若整张卡是深色，必须标明 `inverse`，标题、正文、分割线、数据、图标、按钮、链接全部按深面规则，不能只改标题。可点击整卡需有明确 hover/focus/pressed 反馈；卡中另有按钮时要避免嵌套点击冲突。
3. **数字/HERO**：数值字号可大，但数值与单位/标签都要可读，尤其 10–12px 的次级文字不能用 0.6 左右的不透明度“变高级”。指标白卡上的金数字换为墨绿或深棕；金用于边线、小图标/奖章。天气附属条、日期和提示同样遵循相邻表面对比。
4. **导航与浮层**：手机底部固定栏保持足够不透明，与页面内容明确分离；激活标签同时有颜色+标记（不只颜色）。侧栏菜单、顶部头像区、抽屉标题、下拉选项、占位符、输入值、错误文字一律按其实际表面配色。选择框宽度不足时优先换行/自适应，不用缩小字号糊弄。
5. **动效**：专属教师卡片目前有无限循环金色发光（`globals.css:8027-8034`）；建议改为静态细金边+轻阴影，交互时短暂亮起，并支持 `prefers-reduced-motion`。高级感来自版式、材质和对比，不来自持续闪烁。
6. **移动体验**：以 320/360/390/430px 验证。大卡随屏宽伸缩、长姓名/等级标识换行不溢出；底栏不盖住提交按钮，安全区有效；整页无需横向滚动。触控目标设计目标不小于 44×44px，文字在 200% 缩放下不重叠。

## 4. 落地架构（让后续迭代不再逐页补丁）

### 4.1 一套语义 token，不以组件类型猜文字颜色

将等级原始色板与表面角色分离，建议 `src/constants/portal-theme.ts` 或等价模块统一产出：

```ts
type PortalTheme = {
  canvas: string; surface: string; surfaceSubtle: string;
  onSurface: string; onSurfaceMuted: string;
  hero: string; onHero: string; onHeroMuted: string;
  accent: string; onAccent: string;
  border: string; focus: string;
  nav: string; onNav: string; navInactive: string;
}
```

不要把 `accent` 同时用于文本、实底按钮和数据高亮：这些用途所需对比不同。组件要读取 `--theme-on-surface`、`--theme-on-hero`、`--theme-on-accent` 等，而不是靠祖先 `.dark h2`。可先保留 `TIER_APP`/`MEMBERSHIP_THEME` 作为兼容层，但新的页面与组件仅消费统一语义结构，逐步删重复字段。

建议在门户根容器设置 `data-portal="teacher|parent"` 和 `data-tier="manager|elite|senior|experienced|new|normal|vip|svip"`；大卡显式标记 `data-surface="light|inverse"` 或使用封装组件。`surface` 自己声明背景、文字、次级字、链接、边框、图标变量。禁止把 `color: #F6E9C8 !important` 下沉到所有后代标题。允许针对很旧的页面做有限迁移样式，但必须登记到清理清单，不再层叠追加覆盖。

Ant Design 保持品牌默认暖浅色；需要等级感的 Button、Menu、Tabs、Badge 用组件级 token 或封装类。`Select`、`Dropdown`、`DatePicker`、`Modal`、`Drawer`、`Tooltip` 的浮层必须在手机/桌面都检查真实挂载位置：`providers.tsx` 的 `getPopupContainer` 当前优先找 `mobile-root`，但该根可能带 SVIP 背景类；浮层应明确自己的浅表面，不继承暗字/浅字的全局选择器。Sonner Toast 另有独立样式，也要单测。

### 4.2 主题数据来源

- 教师：沿用 `TeacherLayout` 从当前登录教师 `tierLevel` 解析等级；未知等级使用安全的暖浅色默认值。桌面和手机使用同一主题对象，不能仅手机“专属”深色、桌面不一致。
- 家长：主题必须由**当前选中学生**的 `membershipLevel` 决定；多孩子不同等级时切换要同步修改 HERO、导航、底栏和权益卡。首页的 `localStorage`/自定义事件不能是唯一数据源。跨路由保留选中孩子 ID，但重新校验其是否属于当前家长；数据未到先中性骨架，不显示错误身份主题。退出登录时不得把上个家长的等级留给下个账号。
- 管理员：主题固定为管理端；卡片中的会员/教师等级徽章只影响局部。

## 5. 推荐实施顺序与文件清单

1. 写一张真实页面矩阵与截图基线：教师五档、家长三档，各至少手机/桌面，记录可见性问题；先覆盖首页、课表、考勤、课堂反馈、学习记录/长文章、教师列表和详情、会员权益。没有真实账号时使用只读测试夹具/本地假数据，不改生产会员等级。
2. 在 `src/constants/teacher-tier.ts`、`src/constants/membership.ts` 之上建立统一的语义主题输出；同步修订 `DESIGN.md`：暖浅色是主阅读基底，深色身份面是明确的等级例外。把渐变端点、金色字/底的成对规则写入设计系统。
3. 接通 `TeacherLayout.tsx`、`ParentLayout.tsx`、`MobileLayout.tsx` 的统一根主题与数据来源；修复首屏闪色、多孩子切换、桌面/手机不一致。原有导航点击、徽标、待办、未读数和路由逻辑不得改变。
4. 迁移 HERO、大按钮、大卡、底栏、侧栏、权益卡及浮层。优先改 `src/app/teacher/dashboard/page.tsx`、`src/app/parent/dashboard/client.tsx` 和 `src/app/globals.css` 约 1224–1669、6950–7040、7855–8244 的冲突样式。每迁一个组件就删相应重复/`!important` 补丁，避免双轨并存。
5. 将同一“等级徽标”“HERO 指标卡”“大主按钮”样式封装或集中 token；不要复制八份 CSS。图片、头像、状态徽标只在对应表面里验证，不受页级通配文字规则牵连。
6. 测完再提交。不要为这个主题任务顺手改学生数据、权限、API、部署脚本或收费逻辑；本方案完成前也不要直接上线。

## 6. 验收门槛（未通过不能算完成）

- **对比度**：普通文字与其**实际渲染背景** ≥ 4.5:1；大字 ≥ 3:1；必要的控件边界、图标、选中/焦点识别 ≥ 3:1。见 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [W3C 非文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。渐变最浅处、透明层、禁用以外的每个状态都要测试。品牌 Logo 的例外不能扩展到按钮/徽标文字。
- **配对正确**：深 HERO/权益卡标题浅字、浅大卡/弹窗标题深字；白卡内数字深色。不能出现米白字白卡、金字白卡、白字浅橙/金底。
- **完整状态**：按钮 default/hover/pressed/focus/loading/disabled；卡片普通/选中/可点击；输入框默认/聚焦/错误；Tabs 与底部导航激活/未激活；下拉展开、Drawer、Modal、Toast 均逐项检查。
- **等级矩阵**：教师 5 档 × 手机/桌面；家长 3 档 × 手机/桌面。家长两个孩子等级不同的切换、刷新、跳转、退出再登录必须一致且不闪错色。管理员只显示局部等级标签。
